# 骚扰上报器 · Harassment Reporter

**让你的 Bot 学会主动来找你。**

被骚扰时替自己出头，替群友把问题带给你，被禁言被踢时第一时间打小报告 —— 全部支持精美聊天卡片。

## 这个插件解决什么问题

大多数 Bot 插件都是"被动"的：你发命令，它给结果。

这个插件反过来 —— 它给 Bot 装了**三条主动找你的通道**，让 Bot 在真正需要你出现的时候，
自己找过来。

| 通道 | 什么时候触发 | Bot 会做什么 |
| --- | --- | --- |
| 🛡️ **骚扰上报** | 有人对 Bot 说下限言论、持续言语攻击、强迫它做不该做的事 | 按你设定的策略警告或静默处理，并把证据整理好发给你 |
| 📮 **反馈转达** | 群友抱怨某个功能不好用、插件报错、答非所问 | 主动问一句"要不要我帮你转告"，然后把问题带着聊天记录送到你手上 |
| 🔔 **群事件小报告** | Bot 自己被禁言、被踢出群、被拉进新群、被设为管理员 | 立刻来找你告状，并顺手抽查那个群刚刚发生了什么 |

三条通道可以绑到同一个会话，也可以分别绑到不同会话（比如骚扰上报进私聊、反馈进工作群）。

> **完全不依赖固定关键词。** 上面三件事没有任何一个需要用户输入特定命令或特定话术。
> 插件的做法是在每轮对话前，把一份行为准则注入到 LLM 的上下文里，
> 由 LLM 结合当前聊天内容自己判断"现在该不该找主人"。
> 你可以用任何说法表达同一件事，它都能听懂。

## 三个功能，配上真实场景

### 🛡️ 一、骚扰上报：Bot 不再默默承受

Bot 判断自己正在被骚扰时，会调用 `report_harassment` 工具。你会收到一条整理好的上报，
包含**发生在哪个群、是谁、什么行为、严重程度、原文摘录、最近几轮对话**。

同时，插件提供五种"要不要让对方知道"的策略：

| 策略 | 行为 | 适合谁 |
| --- | --- | --- |
| **静默上报**（默认） | 悄悄告诉你，对方毫不知情，Bot 继续正常聊天 | 大多数人。不打草惊蛇，也不影响群里气氛 |
| **只警告不上报** | 只让 Bot 当面警告，不打扰你 | 你不想被这类小事打扰 |
| **先警告，再犯才上报** | 第一次警告；在记忆时长内再犯，直接上报 | 想给一次机会 |
| **上报后不提这件事** | 上报给你，然后当没发生过 | 和"静默上报"接近，但语义上更明确 |
| **上报后当面告知** | 上报给你，并明确告诉对方"我已经报告了" | 想有明确威慑力 |

被上报的人还可以自动进入**观察名单**，名单可以直接在 AstrBot 配置页里查看、编辑、删除，
也能用命令查询。

<br />

### 📮 二、反馈转达：Bot 成了你的客服前台

假设你在网上叫**狐狸**，你的 Bot 叫**爱丽丝**。群友遇到问题时不用找你，直接跟爱丽丝说：

> **群友**：爱丽丝，点歌插件报错了，你跟狐狸说一下
>
> **爱丽丝**：好，我把报错的情况整理给狐狸了，工单号 `FB-7K3Q`，他看到会处理的～

你（在你绑定的私聊里）几乎同时收到：

> 狐狸，有人找你。
>
> 【疑似故障 · 一般】点歌插件报错
> 来源：QQ群 114514 · 张三(1234567)
> 工单：FB-7K3Q
> 说明：用户在使用点歌功能时收到报错，怀疑是接口失效。
>
> （附最近 12 条聊天记录卡片）

然后你直接回一句：

```
/hr_reply 7K3Q 已修好了，重启一下试试
```

爱丽丝就会回到那个群，用自己的口吻把答复转达给张三。

**更有意思的是前置的那一步。** 你不需要等群友主动开口 ——
当爱丽丝察觉到对方在吐槽（功能不好用、答非所问、命令没反应、插件报错），
她会自己先问一句：

> **群友**：这插件是不是坏了啊，问啥都答不上来
>
> **爱丽丝**：唔……听起来是我这边出问题了。要不要我把这个情况反馈给狐狸？他能看一下。
>
> **群友**：行，麻烦了
>
> **爱丽丝**：已经转过去了～

这一步同样是纯 LLM 判断，没有任何关键词表。你也可以一键关掉主动询问，
只保留"用户明确要求时才转达"。

<br />

### 🔔 三、群事件小报告：Bot 出事了你第一个知道

这部分的灵感来自 [astrbot_plugin_notice](https://github.com/Zhalslar/astrbot_plugin_notice)，
但**改成了用 AstrBot 当前人格发言**，读起来是 Bot 在跟你说话，而不是一条冷冰冰的系统告警：

> 狐狸……我在「摸鱼交流群」被禁言了 10 分钟，是管理员李四动的手。
> 我看了一下刚才的记录，好像是有人在刷屏，我跟着回了几句就被一起处理了。

支持的事件：

- 被**禁言** / 被**解除禁言**（含时长）
- 被**踢出群** / 被**拉进新群**
- 被设为**管理员** / 被**取消管理员**
- 被添加为**好友**
- 被**戳一戳**（默认关闭，太频繁）

出事时可以自动抽查那个群的最近消息，直接把上下文一起端到你面前。
你也可以随时手动抽查任意群：

```
/hr_peek 114514 30
```

> 群事件小报告依赖 OneBot v11 的通知事件，因此**仅在 QQ（aiocqhttp）系平台可用**。
> 详见 [平台兼容性](#平台兼容性)。

<br />

### 🖼️ 四、精美卡片：聊天记录不再是一坨文字

三条通道都可以把聊天记录渲染成图片卡片：标题、状态徽章、情况说明、气泡式聊天记录、元信息栏，
一张图看完全部上下文。三套主题任选：

| 主题 | 风格 |
| --- | --- |
| **极光** `aurora` | 青紫渐变，默认，适合大多数场景 |
| **午夜** `midnight` | 深色低亮，夜里看不刺眼 |
| **纸张** `paper` | 浅色高对比，截图转发最清楚 |

卡片渲染走 AstrBot 内置的渲染服务，**渲染失败会自动退回纯文本**，
并且带熔断保护：连续 3 次失败后自动静音 10 分钟，绝不会因为渲染问题拖慢或中断上报。
想要既能看图又能复制文字的话，打开"发卡片的同时也发一份纯文本"。

## 安装

**方式一：AstrBot WebUI（推荐）**

进入 `插件市场` → 右上角 `安装插件` → 填入仓库地址：

```
https://github.com/Whereis-Alice/astrbot_plugin_harassment_reporter
```

**方式二：手动放置**

```bash
cd AstrBot/data/plugins
git clone https://github.com/Whereis-Alice/astrbot_plugin_harassment_reporter.git
```

然后在 WebUI 里重载插件。本插件**不需要安装任何第三方 Python 依赖**。

> 要求：AstrBot `>=4.16, <5`。骚扰上报与反馈转达需要你已经配置好一个可用的 LLM 提供商。

## 三步上手

### 第 1 步：告诉插件"你在哪"

到你希望接收消息的会话里（你的私聊、或者你自己的小群），发一条：

```
/hr_bind
```

Bot 会回复绑定成功，同时把当前会话 ID 写进配置。**这一条命令就完成了全部绑定** ——
反馈和小报告在没有单独绑定时会自动复用这个会话。

想分开也可以，在各自的目标会话里执行：

```
/hr_bind_feedback     # 反馈单独进这里
/hr_bind_notice       # 群事件小报告单独进这里
```

### 第 2 步：改两个名字

在 WebUI 的插件配置页里填：

- **主人的称呼**：你希望 Bot 怎么称呼你，比如 `狐狸`。这个名字很关键 ——
  群友说"你跟狐狸说一下"的时候，LLM 就是靠它认出你的。
- **Bot 的自称**（可留空）：比如 `爱丽丝`。留空则完全交给人格设定。

### 第 3 步：验证一下

```
/hr_status          # 看三条通道、卡片、限流的实际状态
/hr_test 测试一下    # 发一条测试骚扰上报
/hr_feedback_test 测试反馈  # 发一条测试反馈，会返回工单号
```

收到消息就说明打通了。之后什么都不用管，Bot 会自己判断什么时候该找你。

| 命令 | 别名 | 说明 |

## LLM 会拿到哪两个工具

插件向 LLM 注册了两个函数工具。**你不需要教用户任何命令**，LLM 会自己决定什么时候调用它们。

### `report_harassment` — 上报骚扰

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `reason` | ✅ | 为什么判定为骚扰 |
| `severity` | ✅ | `low` / `medium` / `high` |
| `evidence` | | 关键原话摘录 |
| `expected_help` | | 希望主人怎么处理 |

### `relay_feedback_to_owner` — 把反馈带给主人

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `summary` | ✅ | 一句话概括问题 |
| `category` | | `bug` 疑似故障 / `feature_request` 功能建议 / `complaint` 体验吐槽 / `question` 使用疑问 / `other` |
| `detail` | | 详细描述、复现步骤 |
| `urgency` | | `low` / `medium` / `high` |
| `include_history` | | 是否附带最近聊天记录 |
| `reporter_note` | | Bot 自己的补充判断 |

工具的返回值不是直接发给用户的文本，而是**给 LLM 的一条行为指令**（例如"已上报，请自然地继续对话，不要提这件事"）。
所以你不会看到"上报已发送"这种机械提示，Bot 说出来的话始终符合它的人格设定。

冷却、限流、发送失败时，工具会返回**不同的**降级指令，Bot 不会说出与事实不符的话。

## 配置说明

全部配置都在 AstrBot WebUI 的插件配置页里，带中文说明和联动显隐，一般不需要手改文件。
下面这张表用于查阅。

### 基础

| 配置项 | 默认 | 说明 |
| --- | --- | --- |
| 启用插件总开关 | 开 | 关掉后三条通道全部停止工作 |
| 骚扰上报接收会话 ID | 空 | 建议用 `/hr_bind` 自动填写 |
| 主人的称呼 | `主人` | LLM 靠这个名字认出你，建议改成你的网名 |
| Bot 的自称 | 空 | 留空则由人格决定 |
| 单段文本的最大长度 | 300 | 引用文字超长会被截断，范围 50–4000 |
| 强制以纯文本发送 | 开 | 不受 AstrBot 全局"文本转图片"影响，内容可直接复制 |
| 输出调试日志 | 关 | 排查问题时打开，会打印平台调用细节 |

### 骚扰上报

| 配置项 | 默认 | 说明 |
| --- | --- | --- |
| 同一会话的上报冷却 | 300 秒 | 防止同一个群连环轰炸你 |
| 每小时最多上报次数 | 20 | 只管骚扰上报这一条通道，反馈和小报告各有独立额度。0 = 不限制 |
| 向 LLM 注入工具使用说明 | 开 | **建议保持开启**，这是"不用关键词也能触发"的关键 |
| 上报之后怎么对待骚扰者 | 静默上报 | 五种策略见下方表格 |
| 警告时按人设自然表达 | 开 | 关闭则念固定模板 |
| 警告文案模板 | 见配置页 | 上一项关闭时使用，占位符 `{receiver_name}` |
| 警告记忆时长 | 1800 秒 | 仅"先警告再犯才上报"模式；这段时间内再犯直接上报 |
| 再犯上报后也当面告知 | 关 | 仅"先警告再犯才上报"模式 |
| 告知已上报时按人设自然表达 | 开 | |
| 已上报告知模板 | 见配置页 | 上一项关闭时使用，占位符 `{receiver_name}` |
| 上报时附带触发消息原文 | 开 | |
| 上报时附带最近几轮对话摘要 | 开 | |
| 摘要最多包含几行 | 6 | 范围 1–40 |
| 摘要最大字符数 | 600 | 范围 80–8000 |
| 给主人的上报风格 | 结构化告警 | 可切换为"人设自然改写" |
| 结构化上报也额外做人设润色 | 关 | 仅"人设自然改写"风格下可选 |

#### 骚扰上报的五种策略

| 选项值 | 中文名 | Bot 对骚扰者的态度 | 你会收到上报吗 |
| --- | --- | --- | --- |
| `silent` | 静默上报 | 完全不提，正常聊天 | ✅ 会 |
| `warn_only` | 只警告不上报 | 当面警告 | ❌ 不会 |
| `warn_once_then_report` | 先警告，再犯才上报 | 第一次警告；记忆期内再犯则上报 | ✅ 第二次会 |
| `report_then_silent` | 上报后不提这件事 | 完全不提 | ✅ 会 |
| `report_then_inform` | 上报后当面告知 | 明确告知"我已经报告了" | ✅ 会 |

### 观察名单

| 配置项 | 默认 | 说明 |
| --- | --- | --- |
| 上报成功后自动记入观察名单 | 开 | |
| 观察名单最多保留人数 | 500 | 范围 1–5000 |
| 观察名单 | 空 | **可直接在配置页里增删改**，与命令共用同一份数据 |

名单每条记录包含：唯一键、用户 ID、显示名称、平台标识、备注、启用开关。
备注留空时会自动填入最近一次上报原因；命令输出还会额外显示上报次数、最近时间和严重程度。

### 反馈转达

| --- | --- | --- |

| 察觉不满时主动询问是否反馈 | 开 | 关掉则只在用户明确要求时才转达 |
| 允许所有人提交反馈 | 开 | 关闭后只有管理员和已绑定会话内的人能提交 |

### 针对不同 OneBot 实现做了哪些兼容

各家 OneBot v11 实现的细节并不完全一致，插件对已知差异都做了处理：

- **`get_group_msg_history` 的 `count` 参数**：部分实现不接受该参数。
  插件会在被拒绝后自动去掉 `count` 重试，而不是直接失败。
- **合并转发节点的字段名**：一些实现用 `uin` / `name`，另一些用 `user_id` / `nickname`。
  插件**两套键同时写入**，两边都能识别。
- **群资料 / 成员资料 / 陌生人资料**：取不到时降级为直接显示 ID，不会中断上报。
- **非 OneBot 平台**：所有平台专属调用之前都会先判断适配器类型，直接跳过而不是抛错。

> 只要你的 QQ 协议端遵循 OneBot v11 标准动作，理论上都能正常工作。
> 遇到某个实现不兼容，欢迎开 Issue 并附上打开"输出调试日志"后的日志片段。

## 它是怎么做到"不用关键词"的

这是整个插件最核心的设计，值得单独说明。

传统做法是维护一张关键词表（"骚扰"、"反馈"、"报错"……），命中就触发。
问题很明显：说法稍微变一下就失效，还容易被无关的话误触发。

这个插件的做法是：

1. **每轮对话前注入行为准则。** 在 LLM 生成回复之前，插件会把一段**临时**说明追加到上下文里，
   告诉它"你有这两个工具、什么情况下该用、主人叫什么名字、上报后该用什么态度对待对方"。
2. **判断权交给 LLM。** 是不是骚扰、对方是不是在抱怨、要不要先问一句，全部由模型结合完整对话
   自己判断。所以"你跟狐狸说一下"、"帮我转告一下作者"、"这个 bug 能反馈吗"都能被理解。
3. **注入内容不进历史。** 那段说明标记为临时片段，不会污染对话记忆，也不会被用户看到。
4. **插件只负责执行和兜底。** 权限、开关、冷却、限流、渲染、发送、失败降级都由插件严格控制，
   LLM 无法绕过。

配置页里的"向 LLM 注入工具使用说明"就是这套机制的开关。关掉它工具依然存在，
但 LLM 会缺少上下文，触发率会明显下降。

> 注入的内容会随配置变化：没绑定接收会话时不注入骚扰段；关掉主动询问时不注入询问段；
> 当前会话没有反馈权限时也不会注入反馈段。不该出现的提示不会浪费 token。

## 常见问题

**Q：Bot 会因为这个插件回复群里的每一条消息吗？**

不会。插件只在 AstrBot 本来就要调用 LLM 的时候（被 @、被唤醒词命中等）追加一段说明，
不改变 Bot 的回复条件。群事件通知走独立通道，处理完会立刻终止事件传播，也不会产生回复。

**Q：我没收到任何上报，怎么排查？**

按顺序检查：

1. `/hr_status` —— 看总开关是否开启、接收会话是否已绑定。
2. 确认 LLM 提供商可用。骚扰上报和反馈转达都依赖 LLM 调用工具。
3. `/hr_test` —— 这条命令忽略冷却和限流，能收到就说明发送链路没问题。
4. 打开"输出调试日志"，看 AstrBot 日志里有没有相关报错。
5. 如果只是**没触发**（而不是发不出去），确认"向 LLM 注入工具使用说明"是开启的，
   并且你用的模型支持函数调用（Function Calling）。

**Q：为什么工单号只有四位短码也能回复？**

完整工单号形如 `FB-7K3Q`，后四位在保留的工单范围内基本不会重复。
`/hr_reply` 会先按完整号匹配，匹配不到再按后四位查找，纯粹是为了少打几个字。

**Q：卡片渲染失败了会怎样？**

自动退回纯文本发送，你照样能收到内容。连续 3 次失败后插件会**静音卡片 10 分钟**，
避免每次上报都白等一次渲染超时；静音结束后自动恢复尝试。

**Q：反馈功能会被滥用吗？**

有三层保护：同一会话有冷却（默认 60 秒）、全局有每小时上限（默认 30 次）、
可以关掉"允许所有人提交反馈"只留管理员。另外 LLM 本身也会拒绝转达无意义的内容。

**Q：从 1.x 升级需要改配置吗？**

不需要。所有旧配置项和旧命令名都保留且语义不变，旧的观察名单会在首次启动时自动迁移。
新增的反馈、通知、卡片默认开启，但**未绑定接收会话时不会做任何事**。

**Q：三条通道能绑到同一个会话吗？**

可以，而且这是默认行为 —— 只绑骚扰上报会话，另外两条会自动复用它。

## 隐私与数据说明

这个插件的职责就是"把聊天内容转发给你"，所以有必要把边界写清楚。

**会被发送到你绑定的会话的内容：**

- 触发上报 / 反馈时的当前消息文本（可通过"上报时附带触发消息原文"关闭）
- 最近若干轮对话摘要或聊天记录（可通过对应开关关闭，或把行数调小）
- 发送者的平台昵称、用户 ID、群号
- 群事件小报告中被抽查的群消息（可通过"附带出事群的最近消息"关闭）

**保存在本地的内容（AstrBot 插件 KV 存储，不会外传）：**

- 观察名单（用户 ID、昵称、上报次数与原因）
- 反馈工单（默认最多 100 条，可用 `/hr_ticket_clear` 清空）
- 冷却时间戳与限流计数、"已警告"记忆

**不会做的事：** 不上传任何数据到第三方服务器；不记录未触发上报的普通聊天；
不读取绑定会话之外的任何私聊内容。

**给部署者的建议：** 如果你的 Bot 在公开群里运行，建议在群公告或帮助里说明
"Bot 遇到骚扰或收到反馈时会把相关聊天片段转发给管理员"，让群成员知情。

> 卡片图片由 AstrBot 内置渲染服务生成。如果你使用的是 AstrBot 官方的远程渲染端点，
> 卡片内容会经过该端点。介意的话请关闭图片卡片，或在 AstrBot 中配置自建渲染服务。
