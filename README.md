# 我会打小报告

**让 Bot 学会主动来找你。**

帮群友传话、被骚扰时告状、被禁言被踢时汇报 —— 全都用它自己的口吻说，
还会带上一张最近群聊记录的卡片。

## 先看一个场景

假设你的网名叫**狐狸**，你的 Bot 叫**爱丽丝**。某天下午，星之卡比群里：

> **群友A**：爱丽丝，帮我找一下狐狸，画图插件好像用不了了
>
> **爱丽丝**：好，已经帮你跟狐狸说了，晚点等他回你吧～

同一时刻，你的私聊里收到爱丽丝发来的消息：

> **爱丽丝**：星之卡比群的群友A找你呀狐狸，说是画图插件坏了
>
> —— 群友A（10001）· 星之卡比群（123456）
>
> 〔附一张卡片，上面是那个群刚刚的十几条聊天记录〕

你扫一眼卡片就知道发生了什么，回一句：

```
/hr_back 我看看，应该是模型额度用完了，十分钟后再试
```

爱丽丝转头回到那个群，用自己的语气把这句话带给群友A。

**整个过程没有人念过命令，也没有人填过表单。** 这就是这个插件想做的事。

---

## 它是什么

一句话：**给 Bot 装上「主动来找你」的能力**，让它在真正需要你出现的时候自己找过来。

具体是三件事：

| | 什么时候 | Bot 会做什么 |
| --- | --- | --- |
| 💬 **帮群友传话** | 有人请它带句话给你，或者它自己察觉到有人在吐槽功能坏了 | 用自己的口吻来找你，附上最近的群聊记录。你回一句，它再把话带回去 |
| 🛡️ **被骚扰时告状** | 有人对它辱骂、挑衅、纠缠、恶意消耗 | 按你设定的策略警告或不动声色，然后把情况整理好发给你 |
| 🔔 **群里出事打小报告** | 它自己被禁言、被踢、掉管理、被戳一戳 | 立刻跑来找你，顺手抽一份那个群刚刚在聊什么 |

三件事都可以配一张聊天记录卡片，见下面的[聊天记录卡片](#顺带聊天记录卡片)。

## 它不是什么

**它不是工单系统。** 没有工单号，没有问题分类，没有紧急程度，没有「用户反馈说明」。
2.1.0 之前确实有过这些东西，现在全删掉了 —— 工具调用本来就发生在 Bot 的人格里，
它写出来的话已经是它自己的口吻，再套一层表单只会让它变得像客服机器人。

**它也没有商业诉求。** 这个插件存在的理由只有两条：

- 让 Bot 更灵一点，能像真人一样帮群友喊你一声；
- 你的 Bot 出问题的时候你能第一时间知道，而不是三天后才有人告诉你。

## 一、帮群友传话

### 两种触发方式

**① 有人直接请它传话。** 不需要任何固定句式，意思到了就算：

- 「爱丽丝，点歌插件报错了，你跟狐狸说一下」
- 「帮我转告作者，这个功能能不能加个开关」
- 「你能帮我问问你主人吗」

**② 它自己读出了不满，主动开口问。** 这是更有意思的一半。
当有人在抱怨某个功能不好用、Bot 答非所问、某个插件报错、结果和预期不符时，
它不会干等对方开口，而是自然地问一句：

> **群友B**：这翻译怎么翻得乱七八糟的……
>
> **爱丽丝**：诶，是我没弄明白你的意思吗？要不要我去跟狐狸说一声？

对方点头，它才真的去找你。这一步**完全靠模型读空气，没有任何触发关键词**。

不想要它主动开口，把「察觉不满时主动询问传话」关掉就行。关掉之后它照样会传话，
只是不再自己提这件事。

### 你收到的是什么

一句它亲口说的话，加一行来源标注，再加一张卡片：

```
星之卡比群的群友A找你呀狐狸，说是画图插件坏了

—— 群友A（10001）· 星之卡比群（123456）
```

来源那一行是为了让你一眼看清「谁在哪儿说的」，觉得碍眼可以关掉。

### 回话

| 你输入 | 效果 |
| --- | --- |
| `/hr_recent` | 列出最近谁通过 Bot 找过你，带序号 |
| `/hr_back 我看看，十分钟后再试` | 回给最近找你的那个人 |
| `/hr_back 2 这个下版本加` | 回 `/hr_recent` 列表里的第 2 条 |

Bot 会用自己的人设口吻把话带回原来那个群或私聊，而不是发一条冷冰冰的系统通知。

### 防滥用

三层保护，都可以调：同一个会话有冷却（默认 60 秒）、全局有每小时上限（默认 30 次）、
可以关掉「允许所有人请 Bot 传话」只留管理员。另外模型自己也会拒绝转达无意义的内容。

## 二、被骚扰时告状

Bot 每天要接住各种消息，其中总有一些是纯粹的攻击、纠缠或者试探底线。
这个功能让它在这种时候不再默默承受 —— 它自己判断，然后按你选的策略处理。

**五种策略，选一个：**

| 选项 | Bot 对骚扰者的态度 | 你会收到上报吗 |
| --- | --- | :---: |
| `silent` 静默上报（默认） | 完全不提，继续正常聊天 | ✅ |
| `warn_only` 只警告不上报 | 当面警告 | ❌ |
| `warn_once_then_report` 先警告，再犯才上报 | 第一次警告；记忆期内再犯就上报 | ✅ 第二次 |
| `report_then_silent` 上报后不提这件事 | 完全不提 | ✅ |
| `report_then_inform` 上报后当面告知 | 明确告诉对方「我已经报告了」 | ✅ |

上报内容里可以带触发消息原文和最近几轮对话摘要；也可以把「给主人的上报风格」
切成「人设自然改写」，让它用一句人话跟你说，而不是发一张结构化告警。

被上报过的人会自动进**观察名单**，方便你之后用 `/hr_watchlist` 看看都有谁，
或者用 `/hr_peek 群号` 抽一份那个群最近的聊天记录。

## 三、群里出事了打小报告

灵感来自 [astrbot_plugin_notice](https://github.com/Zhalslar/astrbot_plugin_notice)，
这里换成用 AstrBot 当前人格的口吻来说 —— 不是系统告警，是 Bot 在跟你告状：

> 狐狸……我在星之卡比群被禁言了 10 分钟，是管理员小明干的。
> 我翻了下之前的聊天，好像是因为我连着发了三张图。

**会汇报的事件**（需要 OneBot v11 协议端）：

- 被禁言 / 被解除禁言（含时长）
- 被设为管理员 / 被取消管理员
- 被踢出群 / 被拉进新群 / 有人加了好友
- 被戳一戳（默认关闭，太频繁）

可以用群号白名单只盯几个重要的群。每条小报告还会顺手抽一段那个群的最近消息，
省得你还要回头去问「到底发生了什么」。

## 顺带：聊天记录卡片

上面三件事，Bot 找你的时候都可以附一张卡片。卡片画的是**群里最近的真实发言**：
每条都有独立的昵称、QQ 号和时间，Bot 自己的话靠右、别人的话靠左，看起来就像一段聊天截图。

数据优先走 OneBot 的 `get_group_msg_history`（私聊走 `get_friend_msg_history`），
拿不到接口时才退回 AstrBot 的会话上下文 —— 那种情况下分不清群里具体是谁在说话，
观感会差一些，但至少还有上下文。

卡片是整幅铺满的，没有多余的边框和背景色块，就是一张聊天窗口的截图。
群头像、群友头像默认拉真实的 QQ 头像（`q.qlogo.cn`），拉不到就自动退回彩色首字块，
不影响卡片出图。不想让渲染服务去请求头像的话，把「使用真实 QQ 头像」关掉即可。

清晰度默认是 **2 倍（约 1440 像素宽）+ PNG 无损**，手机上点开放大也不发虚。
还想更细腻就把「卡片清晰度」调到高清（3 倍，约 2160）或超清（4 倍，约 2880）；
在意流量和渲染耗时就关掉「无损画质」，改用高质量 JPEG。
放大只增加像素，版式和字号一点不变 —— 三个档位画出来的是同一张卡片，只是更清楚。

三套配色：

| 主题 | 风格 |
| --- | --- |
| `aurora` 清爽（默认） | 浅色蓝白，像平时的聊天窗口 |
| `midnight` 午夜 | 深色低亮，夜里看不刺眼 |
| `paper` 纸张 | 暖色护眼，长段文字读起来舒服 |

> 卡片只是锦上添花。渲染失败会自动把几句原文贴在正文后面，消息该到的还是会到。
> 连续失败 3 次会静音卡片 10 分钟，免得每次上报都白等一次渲染超时，之后自动恢复。

## 安装

**方式一：AstrBot WebUI（推荐）**

进入 `插件市场` → 右上角 `安装插件` → 填入仓库地址：

```
https://github.com/Whereis-Alice/astrbot_plugin_harassment_reporter
```

**方式二：手动放置**

```bash
cd AstrBot/data/plugins
git clone https://github.com/Whereis-Alice/astrbot_plugin_harassment_reporter.git
```

然后在 WebUI 里重载插件。本插件**不需要任何第三方 Python 依赖**。

> 要求：AstrBot `>=4.16, <5`。传话和骚扰上报依赖 LLM 调用函数工具，
> 所以你需要一个已经配好、且支持 Function Calling 的模型提供商。

## 三步上手

### 第 1 步：告诉它「你在哪」

到你希望接收消息的会话里（你的私聊，或者你自己的小群），发一条：

```
/hr_bind
```

Bot 会回复绑定成功，并把当前会话 ID 写进配置。**这一条命令就够了** ——
传话和小报告在没有单独绑定时会自动复用这个会话。

想分开收也可以，在各自的目标会话里执行：

```
/hr_bind_feedback     # 传话单独发到这里
/hr_bind_notice       # 群事件小报告单独发到这里
```

### 第 2 步：改两个名字

在 WebUI 的插件配置页 →「称呼与身份」分组里填：

- **主人的称呼**：你希望 Bot 怎么叫你，比如 `狐狸`。这个名字很关键 ——
  群友说「你跟狐狸说一下」的时候，模型就是靠它认出你的。
- **Bot 的自称**（可留空）：比如 `爱丽丝`。留空则完全交给人格设定决定。

### 第 3 步：验证一下

```
/hr_status                  # 看三条通道、卡片、限流的实际状态
/hr_test 测试一下            # 发一条测试骚扰上报（忽略冷却和限流）
/hr_feedback_test 测试传话   # 走一遍传话链路，看看文本和卡片长什么样
```

收到消息就说明打通了。之后什么都不用管，Bot 会自己判断什么时候该找你。

### 谁都能用

| 命令 | 别名 | 说明 |
| --- | --- | --- |
| `/harassment_sid` | `/hr_sid` | 查看当前会话 ID（绑定时用得上） |
| `/harassment_help` | `/hr_help` | 列出全部命令 |

### 绑定与状态（需要 AstrBot 管理员）

| 命令 | 别名 | 说明 |
| --- | --- | --- |
| `/harassment_bind_here` | `/hr_bind` | 把**骚扰上报**绑到当前会话（另两条通道默认复用它） |

| `/hr_bind_notice` | — | 把**群事件小报告**单独绑到当前会话 |
| `/harassment_unbind` | `/hr_unbind` | 解绑。参数 `report` / `feedback` / `notice` / `all`，默认 `report` |
| `/harassment_status` | `/hr_status` | 全量状态：三条通道 + 卡片 + 名单 + 限流 |

### 自测（需要 AstrBot 管理员）

| 命令 | 说明 |
| --- | --- |
| `/harassment_test [备注]`（`/hr_test`） | 发一条测试骚扰上报，忽略冷却与限流 |
| `/hr_feedback_test [内容]` | 走一遍完整传话链路，能看到实际的文本和卡片 |

| 命令 | 别名 | 权限 | 说明 |
| --- | --- | --- | --- |
| `/hr_recent [条数]` | `/hr_tickets`、`/hr_ticket` | 管理员或已绑定会话 | 最近谁通过 Bot 找过你，默认 10 条，上限 50 |
| `/hr_back <内容>` | `/hr_reply` | 管理员 | 回给最近找你的那个人 |
| `/hr_back <序号> <内容>` | `/hr_reply` | 管理员 | 回 `/hr_recent` 里的指定序号 |
| `/hr_recent_clear` | `/hr_ticket_clear` | 管理员 | 清空联系记录 |

### 观察名单

| 命令 | 别名 | 权限 | 说明 |
| --- | --- | --- | --- |
| `/harassment_watchlist` | `/hr_watchlist` | 管理员或已绑定会话 | 查看最近 20 条记录 |
| `/harassment_watch_remove <键>` | `/hr_watch_remove` | 同上 | 移除一条，可填用户 ID 或完整键 |
| `/harassment_watch_clear` | `/hr_watch_clear` | 同上 | 清空名单 |

### 群消息抽查（需要管理员 · 仅 OneBot v11）

| 命令 | 别名 | 说明 |
| --- | --- | --- |
| `/hr_peek <群号> [条数]` | `/抽查` | 抓一份该群最近的聊天记录，默认 20 条，上限 100 |

> 旧版本的命令名全部保留。`/harassment_*` 长命令照样能用；
> `/hr_tickets`、`/hr_reply`、`/hr_ticket_clear` 现在分别指向
> `/hr_recent`、`/hr_back`、`/hr_recent_clear`。

## LLM 手里的两个工具

插件给模型注册了两个函数工具。**你不用管它们**，这里写出来只是为了让你知道
Bot 到底能做什么、以及它写进去的东西会原样发给你。

### `relay_feedback_to_owner` — 去找主人说一句话

| 参数 | 说明 |
| --- | --- |
| `message` | 它要对你说的那一整句话 |

就一个参数，故意的。模型用自己的口吻把话写完整（说清是谁、在哪儿、遇到了什么），
插件原样送达，不做二次改写。最近的群聊记录由插件自动附上，模型不需要复述聊天内容。

### `report_harassment` — 上报骚扰

| 参数 | 必填 | 说明 |
| --- | :---: | --- |
| `reason` | ✅ | 为什么它判定这是骚扰 |
| `severity` | ✅ | `low` / `medium` / `high` |
| `evidence` | | 关键原话摘录 |
| `expected_help` | | 希望你怎么介入 |

> **一条底线：没真正送出去的时候，插件绝不会让模型宣称已经上报。**
> 功能没开、会话没绑、撞上冷却、发送失败，模型收到的都是明确的失败说明，
> 它会诚实地告诉用户消息没送到，而不是敷衍一句「已经帮你说了」。

## 配置说明

在 AstrBot WebUI → `插件管理` → `我会打小报告` → `配置` 里改。
配置项按功能分成了**七个分组**，展开哪一组就只看那一组，不用在几十个平铺开关里翻。

最外面还有一个独立的总开关：

| 配置项 | 默认 | 说明 |
| --- | --- | --- |
| **启用插件总开关** | 开 | 关掉之后传话、骚扰上报、群事件小报告会全部停止工作 |

### 📇 称呼与身份

先告诉 Bot 你叫什么、它自己叫什么。上报和传话的时候，它会用这两个名字自然地提起你。

| 配置项 | 默认 | 说明 |
| --- | --- | --- |
| 主人的称呼 | `主人` | Bot 用这个名字叫你，比如 `狐狸`。模型判断「要不要找你」时也认这个名字 |
| Bot 的自称 | 空 | 比如 `爱丽丝`。留空则由当前人格自行决定，一般不用填 |

### 🛡️ 骚扰上报

| 配置项 | 默认 | 说明 |
| --- | --- | --- |
| 骚扰上报接收会话 ID | 空 | 建议直接用 `/hr_bind` 自动填写 |
| 上报之后怎么对待骚扰者 | 静默上报 | 五种策略见[上面的表格](#二被骚扰时告状) |
| 同一会话的上报冷却 | 300 秒 | 同一个群在冷却期内只上报一次。范围 0–86400 |
| 每小时最多上报次数 | 20 | 0 = 不限制。范围 0–500 |
| 警告时按人设自然表达 | 开 | 关掉则念下面那条固定模板 |
| 警告文案模板 | 见配置页 | 上一项关闭时使用，占位符 `{receiver_name}` |
| 警告记忆时长 | 1800 秒 | 仅「先警告再犯才上报」模式；这段时间内再犯直接上报 |
| 再犯上报后也当面告知 | 关 | 仅「先警告再犯才上报」模式 |
| 告知已上报时按人设自然表达 | 开 | 关掉则念下面那条固定模板 |
| 已上报告知模板 | 见配置页 | 上一项关闭时使用，占位符 `{receiver_name}` |
| 上报时附带触发消息原文 | 开 | |
| 上报时附带最近几轮对话摘要 | 开 | |
| 摘要最多包含几行 | 6 | 范围 1–40 |
| 摘要最大字符数 | 600 | 范围 80–8000 |
| 给主人的上报风格 | 结构化告警 | 可切成「人设自然改写」，让它用一句人话跟你说 |

### 👀 观察名单

被上报过的人会自动进这份名单，方便你之后抽查他们最近说了什么。

| 配置项 | 默认 | 说明 |

## 平台兼容性

**核心能力（传话、骚扰上报、卡片渲染）与平台无关**，任何 AstrBot 支持的平台都能用。
只有需要读群历史、读群资料、监听群事件的部分依赖 OneBot v11 协议。

| 平台 / 协议端 | 帮群友传话 | 骚扰上报 | 群事件小报告 | 真实群聊记录卡片 | `/hr_peek` 抽查 |
| --- | :---: | :---: | :---: | :---: | :---: |
| **NapCat** | ✅ | ✅ | ✅ | ✅ | ✅ |
| **LLBot**（原 LLOneBot / LuckyLilliaBot） | ✅ | ✅ | ✅ | ✅ | ✅ |
| **SnowLuma** | ✅ | ✅ | ✅ | ✅ | ✅ |
| **Lagrange.OneBot** | ✅ | ✅ | ✅ | ✅ | ✅ |
| **go-cqhttp** | ✅ | ✅ | ✅ | ✅ | ✅ |
| Telegram / Discord / QQ 官方接口 / 微信等 | ✅ | ✅ | ❌ | ⚠️ 退回会话上下文 | ❌ |

在 AstrBot 里，上面这些 QQ 协议端都通过同一个 `aiocqhttp` 适配器接入，插件只要认出
这个适配器就会启用 OneBot 专属能力，不区分具体是哪一家实现。

### 针对不同 OneBot 实现做的兼容

各家实现的细节并不完全一致，已知差异都做了处理：

- **`get_group_msg_history` 的 `count` 参数**：部分实现不接受它。
  插件被拒绝后会自动去掉 `count` 重试，而不是直接放弃。
- **`get_friend_msg_history`（私聊历史）**：只有部分实现提供。
  探测到不支持之后，本次运行里就不再重复请求，直接退回会话上下文。
- **合并转发的节点字段名**：go-cqhttp 和 SnowLuma 习惯 `uin` / `name`，
  NapCat 和 LLBot 兼容 `user_id` / `nickname`。插件**两套键同时写入**，两边都认。
  连续 3 次失败才判定这个实现不支持合并转发，避免偶发网络抖动让整个运行周期都退化。
- **群资料 / 成员资料 / 陌生人资料**：取不到就直接显示 ID，不会中断上报。
- **非 OneBot 平台**：所有平台专属调用之前都会先判断适配器类型，跳过而不是抛错。

> 只要你的协议端遵循 OneBot v11 标准动作，理论上都能正常工作。
> 遇到某个实现不兼容，欢迎开 Issue 并附上打开「输出调试日志」后的日志片段。

## 它是怎么做到「不用关键词」的

这是整个插件最核心的设计，值得单独说明。

传统做法是维护一张关键词表（「骚扰」「反馈」「报错」……），命中就触发。
问题很明显：说法稍微变一下就失效，还容易被无关的话误触发。

这个插件的做法是：

1. **每轮对话前注入一段行为准则。** 在模型生成回复之前，插件会把一段说明追加到上下文里，
   告诉它「你有这两个工具、什么情况下该用、主人叫什么名字、上报后该用什么态度对待对方」。
2. **判断权完全交给模型。** 是不是骚扰、对方是不是在抱怨、要不要先问一句，
   全部由模型结合完整对话自己判断。所以「你跟狐狸说一下」「帮我转告作者」
   「这个 bug 能反馈吗」都能被理解。
3. **注入内容不进历史。** 那段说明被标记为临时片段，不会污染对话记忆，也不会被用户看到。
4. **插件只负责执行和兜底。** 权限、开关、冷却、限流、渲染、发送、失败降级都由插件严格控制，
   模型绕不过去。

配置页里的「向 LLM 注入工具使用说明」就是这套机制的开关。关掉它工具依然存在，
但模型会缺少上下文，触发率明显下降。

> 注入内容会随配置变化：没绑定骚扰上报会话时不注入骚扰段；
> 当前会话没有传话权限时不注入传话段；不该出现的提示不会浪费 token。

## 从 2.0 升级

**配置会自动迁移，你不需要重填。** 首次加载 2.1.0 时，插件会把旧的平铺配置搬进新的七个分组
（只跑一次，旧字段保留作备份），日志里会打印迁移了多少项。

要注意的几处变化：

- **传话不再是工单系统。** 工单号、问题分类、紧急程度、`reporter_note` 全部删除；
  LLM 工具 `relay_feedback_to_owner` 的参数从 6 个精简成 1 个 `message`。
- **卡片内容换了。** 从「模型会话上下文」换成「群里最近的真实发言」，走 OneBot 接口读取。
- **三个命令改名。** `/hr_tickets`、`/hr_reply`、`/hr_ticket_clear` **保留为别名**，
  但行为指向 `/hr_recent`、`/hr_back`、`/hr_recent_clear`。`/hr_back` 不再需要工单号，
  改成可选的序号。
- **删掉 6 个配置项**：`natural_language_report_to_owner`、`feedback_include_history_default`、
  `feedback_history_lines`、`feedback_persona_rewrite`、`feedback_ticket_max_entries`、`card_keep_text`。
- **历史工单不再读取。** 旧 KV 键 `feedback_tickets_v1` 保留在本地但不再使用，
  新的联系记录存在 `feedback_contacts_v1`。

完整变更见 [CHANGELOG.md](CHANGELOG.md)。

## 常见问题

**Q：Bot 会因为这个插件回复群里的每一条消息吗？**

不会。插件只在 AstrBot 本来就要调用 LLM 的时候（被 @、被唤醒词命中等）追加一段说明，
不改变 Bot 的回复条件。群事件通知走独立通道，处理完立刻终止事件传播，也不会产生回复。

**Q：我什么都没收到，怎么排查？**

按顺序检查：

1. `/hr_status` —— 看总开关是否开启、接收会话是否已绑定。
2. 确认 LLM 提供商可用，且模型**支持函数调用（Function Calling）**。
3. `/hr_test` —— 这条命令忽略冷却和限流，能收到就说明发送链路没问题。
4. `/hr_feedback_test` —— 单独验证传话链路和卡片。
5. 打开「输出调试日志」，看 AstrBot 日志里有没有相关报错。
6. 如果只是**没触发**（而不是发不出去），确认「向 LLM 注入工具使用说明」是开着的。

**Q：为什么卡片上是会话上下文，不是真实的群聊记录？**

说明没能从平台读到群历史，插件退回了兜底数据源。常见原因：不是 OneBot v11 平台、
协议端没实现 `get_group_msg_history`、或者 Bot 没有读取历史的权限。
打开调试日志能看到具体是哪一步失败的。

**Q：卡片渲染失败了会怎样？**

自动退回纯文本，正文照样送到，几句聊天原文会贴在正文后面。
连续 3 次失败会静音卡片 10 分钟，避免每次上报都白等一次渲染超时，之后自动恢复尝试。

**Q：Bot 会不会明明没送出去，却跟群友说「已经帮你说了」？**

不会，这是插件专门守住的一条底线。功能没开、会话没绑、撞冷却、发送失败，
模型拿到的都是明确的失败说明，它会诚实地告诉对方消息没送到。

**Q：三条通道能绑到同一个会话吗？**

可以，而且这是默认行为 —— 只绑骚扰上报会话，另外两条会自动复用它。

**Q：从 1.x 升级需要改配置吗？**

不需要。旧配置和旧命令名都保留，观察名单会在首次启动时自动迁移。
新增的功能默认开启，但**未绑定接收会话时不会做任何事**。

## 隐私与数据说明

这个插件的职责就是「把聊天内容转发给你」，所以有必要把边界写清楚。

**会被发送到你绑定的会话的内容：**

- 触发上报 / 传话时的当前消息文本（可关闭「上报时附带触发消息原文」）
- 最近若干条群聊记录或对话摘要（可关闭对应开关，或把条数调小）
- 发送者的平台昵称、用户 ID、群号与群名
- 群事件小报告中被抽查的群消息（可关闭「附带出事群的最近消息」）

**保存在本地的内容（AstrBot 插件 KV 存储，不外传）：**

- 观察名单（用户 ID、昵称、上报次数与原因）
- 联系记录（默认最多 50 条，可用 `/hr_recent_clear` 清空）
- 冷却时间戳、限流计数、「已警告」记忆

**不会做的事：** 不上传任何数据到第三方服务器；不记录未触发上报的普通聊天；
不读取绑定会话之外的任何私聊内容。

**给部署者的建议：** 如果你的 Bot 在公开群里运行，建议在群公告或帮助里说明一句
「Bot 遇到骚扰或替人传话时会把相关聊天片段转发给管理员」，让群成员知情。

> 卡片图片由 AstrBot 内置渲染服务生成。如果你用的是 AstrBot 官方远程渲染端点，
> 卡片内容会经过该端点。介意的话请关闭图片卡片，或在 AstrBot 里配置自建渲染服务。
